# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Firefly Focus — Pomodoro Timer & Tasks** — Chrome-розширення (Manifest V3, `minimum_chrome_version: 116`), версія **2.5.0**. Спокійний Pomodoro-таймер: side panel, плаваючий віджет на сторінках, задачі з дедлайнами, анімація світлячків, 3 теми, 7 мов, звуки через Web Audio. Повністю локальне — без акаунтів, аналітики й мережевих запитів.

- Чистий HTML/CSS/JS, **без збірки і без залежностей** — файли підключаються як є.
- Дві цілі з одного коду: **розширення** (головна) і **PWA-застосунок** — див. розділ нижче.
- Публікація в Chrome Web Store ще не відбулася (лістинг готовий у `STORE-LISTING.md`).

## Запуск / тестування

Немає ні тестів, ні лінтера. Перевірка ручна: `chrome://extensions` → Developer mode → **Load unpacked** → обрати цю папку → після правок натискати **Reload** на картці розширення (для content script ще й перезавантажити вкладку).

**Застосунок** треба віддавати з сервера, а не з `file://` — інакше не буде ні service worker, ні встановлення. Будь-який статичний сервер із кореня репозиторію, далі `http://localhost:<порт>/`. Service worker працює тільки на `https` або `localhost`.

## Архітектура

Джерело істини — `service_worker.js`. Весь стан живе одним об'єктом у `chrome.storage.local` під ключем **`pomodoro`**: `{ mode, running, endsAt, remainingMs, sessionsDone, settings, tasks, stats }`.

- UI (side panel, віджет) **не рахує таймер сам** — він виводить `endsAt - Date.now()` і раз на 500 мс перемальовується (`setInterval(render, 500)`).
- Обидва UI шлють повідомлення `chrome.runtime.sendMessage({ type, ... })` у service worker (типи: `GET_STATE`, `START`, `PAUSE`, `SKIP_STAGE`, `RESET_TIMER`, `RESET_STATS`, `SAVE_SETTINGS`, `ADD_TASK`, `SET_TASK_DEADLINE`, `TOGGLE_TASK`, `DELETE_TASK`, `CLEAR_DONE_TASKS`, `OPEN_SIDE_PANEL`, `CLOSE_OFFSCREEN`) і отримують `{ ok, state }`.
- Синхронізація між контекстами — через `chrome.storage.onChanged`: обидва UI слухають зміни ключа `pomodoro` і перемальовуються.
- Завершення етапів — через `chrome.alarms` (`pomodoro-end-alarm`, `pomodoro-warning-alarm`), тому таймер працює і з закритою панеллю. `restoreAlarmIfNeeded()` при старті браузера доганяє пропущене завершення.
- Звук: SW → `ensureOffscreenDocument()` → повідомлення `{ target: "offscreen", type: "PLAY_SIGNAL", kind, theme }` → `offscreen.js` синтезує фразу через Web Audio. Offscreen-документ **сам закривається** (~1 с після останнього звуку, шле `CLOSE_OFFSCREEN`), інакше Chrome показує постійний індикатор фонового документа — не ламати цю логіку.

## Дві цілі: розширення і застосунок

Один код, дві оболонки. Розширення — головна ціль і живе в корені як було. Застосунок (PWA) **нічого не дублює**: він завантажує ті самі `sidepanel.html`, `fullscreen.html`, `sidepanel.js`, `fullscreen.js`, `service_worker.js`, `offscreen.js`, `shared.js`, `buddy.js` і той самий CSS — просто підкладає під них адаптер замість `chrome.*`.

| Файл | Роль |
|---|---|
| `index.html` | Оболонка застосунку: вікно з панеллю |
| `ambient.html` | Оболонка застосунку: повноекранний таймер |
| `app/shim.js` | Адаптер `chrome.*` → звичайний веб |
| `app/boot.js` | Витягує розмітку зі сторінки розширення й вантажить скрипти в правильному порядку |
| `app/app.css` | Тільки розкладка колонки у вікні |
| `manifest.webmanifest` | Маніфест PWA (не плутати з `manifest.json` розширення) |
| `sw.js` | Офлайн-кеш PWA (**не плутати** з `service_worker.js` — це рушій таймера) |

**Головне правило: у застосунку не має бути власної копії UI.** Щойно з'явиться другий `index.html` із розміткою таймера — правки доведеться робити двічі, і вони розійдуться. `boot.js` бере `<body>` зі сторінки розширення через `fetch` + `DOMParser`, як це вже робить шторка налаштувань у `fullscreen.js`.

Що знає адаптер: `runtime.sendMessage/onMessage/getURL/getContexts`, `storage.local` + `onChanged`, `alarms`, `notifications`, `action.setBadgeText`, `offscreen`, `tabs.create`. Чого немає навмисно: `runtime.id` (щоб код content script коректно вимикався) і `sidePanel` (`service_worker.js` це вже перевіряє).

Пастки, які легко зламати:

1. **Порядок завантаження в `boot.js`** — `shared.js` і `buddy.js` перед скриптом сторінки, а рушій перед звуком. `boot.js` перемикає `__fireflyShim.setContext()` перед кожним файлом: у розширенні `service_worker.js` і `offscreen.js` живуть у різних контекстах і браузер сам маршрутизує повідомлення, а тут вони в одній сторінці. Без цих міток `{ target: "offscreen", type: "PLAY_SIGNAL" }` дійшло б і до рушія, який на невідомий тип кидає помилку.
2. **Тільки одне вікно володіє таймером.** Інакше друга вкладка відіграє те саме завершення етапу вдруге — два звуки, дві нотифікації. Лідер обирається через `navigator.locks`: коли вікно-лідер закривають, блокування саме переходить до наступного, і той дозброює будильники.
3. **`offscreen.js` створює `AudioContext` на кожен сигнал.** Offscreen-документу це можна будь-коли, звичайній сторінці — ні: контекст, створений через хвилини після останнього кліку, стартує `suspended`, і сигнал глухне. Тому `shim.js` підмінює `AudioContext` так, щоб той сам робив `resume()`.
4. **`sw.js` мусить лежати в корені.** Його область дії — його тека; з `app/sw.js` запити до `shared.js` не перехоплювались би й офлайн не працював. З тієї ж причини в корені лежать `index.html` і `ambient.html`.
5. **Список `PRECACHE` у `sw.js` — ручний.** Новий файл, який потрібен застосунку, треба туди додати, інакше офлайн його не знайде. І підняти `CACHE`, бо встановлена копія віддаватиме старий.
6. **Плаваючого віджета в застосунку немає** і бути не може — це content script. Це єдина фіча, яка лишається ексклюзивом розширення.

## Правила, які легко порушити

1. **Два окремі i18n-словники** — `messages` у `service_worker.js` (нотифікації) і `i18n` у `shared.js` (панель + повний екран). `floating_widget.js` має **третій**, урізаний, бо це content script і `shared.js` він не бачить. Мови: `uk, en, de, es, it, sk, cs` (fallback — `uk`). Новий рядок = оновити всі, де він потрібен; нова мова = **всі три** + `<select id="languageSelect">` у `sidepanel.html` + масив `languages` у `normalizeSettings()`. Назви тем (Midnight/Daylight/Sage) і стилів звуку лишаються англійською в усіх мовах.
   `shared.js` — звичайний скрипт, а не модуль: він оголошує глобальні `i18n` і `FIREFLY_PALETTE`, тому в HTML має йти **перед** `sidepanel.js`/`fullscreen.js`. Так само `buddy.js` (глобальний `FireflyBuddy`) — між ними.
2. **Нове налаштування** торкається: `DEFAULT_SETTINGS` + `normalizeSettings()` (service_worker.js), input у `sidepanel.html`, `collectSettingsFrom()` + `applySettingsTo()` (shared.js), підписи в i18n ×7 мов. `normalizeSettings()` — єдине місце валідації/клемпів; UI шле сирі значення.
   **`timerPreset` — навмисний виняток**: це не налаштування й у стан не потрапляє. `derivePreset()` щоразу виводить його з чотирьох тривалостей, тому мітка не може розійтися з числами. Не додавати його в `DEFAULT_SETTINGS`/`normalizeSettings`/`collectSettingsFrom`. Новий пресет = рядок у `TIMER_PRESETS` + `<option>` у `sidepanel.html` + підпис в i18n ×7.
   Форма налаштувань існує **в одному екземплярі** — у `sidepanel.html`. Повноекранна шторка клонує її звідти через `fetch` + `DOMParser` (`buildSettingsSheet()` у fullscreen.js), тому новий інпут з'являється там сам собою. Читання/запис форми — теж спільні (`collectSettingsFrom`/`applySettingsTo` беруть `root`, і те, чого в цьому root немає, підставляють зі стану). Не дублювати цю розмітку в fullscreen.html.
   **Що зберігається без кнопки «Зберегти»**: тема, мова і **розмір тексту** — вони застосовуються й записуються в момент зміни, решта форми чекає кнопки. Розмір тексту веде `bindTextScale()` у shared.js, одна на панель і шторку: кожен клік по стрілках зберігає одразу (тож віджет на сайтах масштабується разом із панеллю), а набір з клавіатури лише показує прев'ю й зберігається по Enter або втраті фокусу. Дві пастки. Проміжні значення поза 80–140 («1» на шляху до «120») прев'ю **не** чіпають — інакше весь інтерфейс сіпався б до 80 % на кожну цифру. І цикл `render()` кожної сторінки **не** мусить перезаписувати `--text-scale`, поки поле у фокусі: раніше саме він за пів секунди відкочував прев'ю, і здавалося, що стрілки «не працюють» без кнопки.
3. **Не перемальовувати список задач на кожен тік.** Рендер задач сторінок розширення один на всі — `renderTasksInto()` у shared.js: `simple` = чекбокс + текст, `simple + withDeadline` = ще й чип дати під текстом (плаваюча картка повного екрана), повний рядок = ще й кнопка видалення (панель і шторка). Сам чип будує `buildDeadlineInput()` — один контрол на всі поверхні. Кожен виклик має бути за відбитком `tasksSignature()` — без нього нативний date picker дедлайну закривається кожні 500 мс (це вже був баг, виправлений у 2.5.0). Відбитків **чотири незалежні**: `lastTasksSignature` у панелі, `cardSignature` і `sheetSignature` у повному екрані, `tasksSignature` у `floating_widget.js`. Віджет свій відбиток отримав тільки тоді, коли в нього з'явились дедлайни — доти він спокійно перебудовував список щотіка, бо там не було чого закривати.
   **Додати задачу можна з усіх трьох поверхонь** — панель, плаваюча картка повного екрана, віджет на сторінці. Усі шлють той самий `ADD_TASK`, розмітка форми в кожної своя (у віджета вона мусить бути своя — це content script). Дві пастки. У повному екрані фокус в інпуті мусить тримати `markActive()`, інакше ambient-згасання забирає картку через 4 с посеред набору. У віджеті інпут мусить гасити `keydown`/`keyup`/`keypress`: це чужа сторінка, а через shadow-retargeting сайт бачить у `event.target` не `INPUT`, а хост-`div`, тому його власні гарячі клавіші **не** самоусуваються — набране «/» відкрило б їхній пошук. Спинити вдається лише фазу спливання; слухачі сайту в capture однаково бачать клавіші, бо capture доходить до хоста раніше, ніж до інпута.
4. **Вигляд таймера** (`timerFace`: `ring`/`digits`/`breathe`) — це звичайне налаштування за правилом 2. Розмітка кільця **не змінюється** ніколи; кожен вигляд лише перевдягає її через `body[data-face]` у `sidepanel.css`, тому панель і повний екран ділять один набір правил. Віджет завжди кільце — його CSS окремий. Дихання вимкнене при `body[data-running="false"]` і при `prefers-reduced-motion`. Вигляд `digits` малює лінійну смугу з `--progress-pct` (конічний кут у градусах для неї не годиться), тому обидві сторінки виставляють **і** `--progress`, **і** `--progress-pct`.
   Розміри циферблата в панелі веде одна змінна **`--ring-size`** на `.ring`: від неї похідні і `padding` внутрішнього диска (0.065), і кегль цифр (0.215). Щоб змінити масштаб — правити тільки діаметр, решта перерахується. Підказка (`#hint`) навмисно **поза** кільцем: три рядки поради всередині кола конкурували з часом і тиснули на цифри.
   **Кегль цифр рахувати від контейнера, не від вікна.** Цифри лежать у grid-комірці: щойно вони ширші за неї, колонка розтягується і весь надлишок іде вправо — час помітно «їде» при переході 5:00 → 25:00 → 120:00. Це вже був баг. Найдовший рядок — `120:00`, ≈2.93em завширшки.

5. **Теми**: `midnight` (dark, default), `daylight` (light), `sage` (green). Палітри: midnight — **«Moon»** (глибокий фіолет + маджента), daylight — **«Twine»** (бузок-рум'янець + троянда/барвінок/орхідея), sage — зелена поверхня + бурштин. Кольори живуть у **чотирьох** місцях: `body[data-theme]` у `sidepanel.css`; `.widget[data-theme]` в інлайн-CSS `floating_widget.js`; `FIREFLY_PALETTE` (окремо в sidepanel.js і floating_widget.js); колір бейджа в `updateBadge()` (service_worker.js) — там навмисно глибші відтінки, щоб читалось на світлому й темному тулбарі. Нова тема = усі ці місця + `colorThemes` у `normalizeSettings()` + `<select id="themeSelect">`.
   **Готові палітри майже ніколи не лягають напряму**: пастельні свотчі провалюють контраст як текст (≤2:1), майже-чорні — як акценти. Беріть їх на фони/чипи, а для тексту й акцентів виводьте тони тієї ж барви, доведені до 4.5:1. Перевіряти обов'язково: `.mode` (акцент на картці), `.hint`/`--muted`, `--subtle` у статистиці, пара `--on-accent`/`--accent` на `.primary`, пара `--accent-text`/`--accent-soft` на чипі й вторинних кнопках.
6. **Ліміти даних**: ≤30 задач, текст ≤90 символів, дедлайн — рядок `YYYY-MM-DD` або `null` (`normalizeDeadline`). Дедлайни: протерміновано = червоне (`overdue`), ≤2 днів = бурштинове (`soon`) — `deadlineUrgency()` живе в shared.js, але **продубльована** у floating_widget.js (content script не бачить shared.js). Міняти логіку — в обох місцях. Те саме з розміткою чипа: `buildDeadlineInput()` у shared.js і його копія в рендері віджета. Поставити дедлайн можна з усіх чотирьох поверхонь (панель, шторка, картка повного екрана, віджет) — усі шлють `SET_TASK_DEADLINE`. У віджеті `.task input` мусить бути звужене до `input[type="checkbox"]`, інакше правило чекбокса (15×15) з'їдає поле дати; і `color-scheme` на `.widget` задає, у якій темі малюється нативний календар.
7. **Віджет на сайтах — це два шматки**, кожен зі своєю позицією. **Таймер** (кільце, час, Старт/Пауза; клік по часу відкриває панель; позиція під старим ключем `pomodoroFloatingPosition`) з **шухлядою задач під ним** — ручка ⌃ на нижньому краї таймера згортає її, рядок «+ Нова задача» відкриває поле. І **кіт** — кіт із `buddy.js` на поличці-пігулці з кнопками 🐾 (гуляти) · ⚽ (гратися) · мурчання (`pomodoroBuddyPosition`). Тягнуть обидва за будь-яке місце, крім контролів; кота — просто за кота: короткий клік гладить його (мурчання), рух — перетягує. Тому захоплення вказівника вмикається лише тоді, коли рух справді почався, і клік після перетягування гаситься в capture-фазі — інакше або кіт не мурчав би від кліку, або мурчав би після кожного перетягування.
   **Два режими кота, вибір зберігається** (`pomodoroBuddyMode`, окремий ключ у `chrome.storage.local`, не налаштування — як і позиції). «Гратися» (за замовчуванням): кіт лишається на поличці (доріжка завширшки з поличку, 232 px) і грається з м'ячиком — `activity: "play"` у рушії. «Гуляти»: хост кота **переїжджає** з полички в `.floor` — смугу на всю ширину вкладки внизу, прозору для кліків, — і кіт сам ходить нею (`activity: "roam"`), а пігулка лишається на місці з порожньою поличкою. Дві пастки: `.floor` має стати видимою **до** того, як кіт туди переїде, інакше рушій міряє доріжку нульової ширини й садить кота в кут; і при зміні режиму висота шматка змінюється, тож `setBuddyMode()` зсуває позицію на цю різницю, щоб пігулка не стрибала.
   **Три різні способи «прибрати» віджет — не плутати.** `×` (з'являється при наведенні) ховає один шматок лише до перезавантаження сторінки (`dismissed.timer`/`dismissed.buddy`, у сховище не йде; кіт на підлозі ховається разом зі своєю пігулкою). Ручка ⌃ згортає задачі під таймером (`floatingWidgetCompact` — зберігається, `.timer-piece[data-folded]`). Постійне вимкнення обох — тумблер `floatingWidgetEnabled`; самого кота вимикає `studyBuddyEnabled`, і тоді лишається пігулка без кота.
   **Кіт на сайтах малюється не під час завантаження сторінки**, а в її першу тиху мить (`requestIdleCallback`): малюнок коштує кілька десятків мілісекунд, і кожен сайт платив би ними за свій старт. З тієї ж причини кадри ходи малюються лише тоді, коли кіт справді йде, а голова — один раз, з очима поверх.
   `floatingWidgetCompact` — виняток із правила 2: інпута в панелі немає, він перемикається з самого віджета. Але його **обов'язково** треба протягувати через `collectSettings()` у sidepanel.js, інакше будь-яке збереження налаштувань із панелі скине віджет назад у розгорнутий стан. Те саме стосується `widgetMode`.
   **Вимкнення розширення віджет мусить прибрати сам.** Chrome не знімає content script із уже відкритих сторінок, коли розширення вимикають, видаляють або перезавантажують: скрипт лишається жити, відрізаний від розширення, і віджет далі відлічував би таймер, який ніхто не може ні запустити, ні зупинити (це був баг: «вимикаю розширення, а панелька не зникає»). Ознака — зникає `chrome.runtime.id`; її перевіряє кожен тік (`tick()` → `extensionAlive()`), і `teardown()` знімає хост, таймери й слухачі. Глобальна мітка `window.__POMODORO_FLOATING_WIDGET__` — об'єкт із `teardown`, а не `true`: нова копія скрипта не поступається старій, а перебирає сторінку на себе.
8. **Котик-компаньйон** (`studyBuddyEnabled`) — рудий піксель-арт кіт, трохи мейнкун, в обручі кольору шавлії з двома антенками-світлячками. Увесь живе в **`buddy.js`** (малюнок, рушій, мурчання); сторінка лише кличе `buddy.sync({ enabled, running, night })` зі свого `render()`. Ходить у панелі й на повному екрані, а на сайтах грається з м'ячиком на поличці плаваючого віджета або гуляє низом вкладки (правило 7). Ключ налаштування лишився `studyBuddyEnabled` — він ніколи не називав тварину.
   **Що кіт робить сам, задає `activity`** (`create(host, { activity })`, змінюється `setActivity()`). `"timer"` — кіт панелі й повного екрана: ходить, поки таймер іде; сідає, щойно його зупинили; а якщо простій триває `DOZE_AFTER_MS` (14 с) — лягає, згортається й засинає. `"roam"` — гуляє доріжкою сам: іде до випадкового місця, сидить 2.5–8 с, зрідка дрімає, і знову в дорогу (`roamBrain`). `"play"` — сидить на місці й грається з м'ячиком (`playBrain`): повертається до нього, б'є лапою, коли той у межах досяжності — **від грудей до кінця замаху**, бо м'ячик, що зупинився під грудьми, інакше лишався «задалеко для удару і заблизько, щоб іти», і кіт завмирав, — а коли той відкотився й зупинився, підходить. М'ячик — окремий шматок поза кадром кота: котиться з тертям, відскакує від країв доріжки й часом прокочується під котом на інший бік. Удар — це **ближня передня лапа сидячого кота, винесена в окремий шар** (`sitNear()`), що обертається від плеча (`SIT.shoulder`); у звичайній позі вона виглядає так само, як коли була частиною тіла. Мурчання будь-якої з активностей садить кота на місце. Перехід між позами — присідання, заміна спрайта на самому дні й пружне розпрямлення (`startTransition`/`stepTransition`); ланцюжок веде рушій, а не CSS.
   **Малюнок не зберігається картинками.** Кожна частина описана фігурами (`blob`, `tri`, `tube`, `wire`) плюс кількома вручну поставленими пікселями обличчя і раз на сторінку растеризується в `<canvas>` — один піксель полотна на піксель арту. CSS збільшує їх через `image-rendering: pixelated`. `--buddy-size` — лише бажана ширина: `measure()` округлює масштаб до **цілої кількості фізичних пікселів на піксель арту** (інакше пікселі виходять різного розміру) і пише його як `--px` на `.buddy`; з `--px` CSS рахує і доріжку, і кожен шар. Координати малюнка «логічні» — лапи стоять на рядку 57; полотно `FRAME` 68×66 зміщує їх на `(ox, oy)`, щоб над сидячим котом лишався запас для антенок.
   **Голова одна на всі пози й дивиться на глядача** (тіло — у профіль). Вона симетрична навмисно: на розвороті кіт дзеркалиться, і морда лишається тією самою. Очі 5×6, зелені з бліками, варіанти `open`/`look`/`half`/`shut`/`happy` (^ ^ під час мурчання); рот — «ω». Обруч і антенки — **шавлія в усіх темах** (раніше брали `--accent`), шерсть теж не залежить від теми: це персонаж, а не інтерфейс.
   **Шари, а не один спрайт**: тінь, хвіст, дальні лапи, тіло, ближні лапи, кінчик хвоста, голова з вусами й антенками — кожен свій елемент, і рухаються вони **лише `transform`** із `will-change`. Один цикл `requestAnimationFrame` (не частіше 60 кадрів на секунду) веде все; він **стоїть**, коли кота не видно — вкладка прихована, доріжку прокручено з екрана, кота вимкнено. Таймер буває відкритий годинами, тож це питання батареї.
   **Що рухається і як**: дихання — крива `cubic-bezier` (`EASE_INHALE`/`EASE_EXHALE`); у сидячій і лежачій позах тіло тягнеться **від підлоги**, щоб лапи не їздили. Голова йде за тілом на пружині із запізненням; антенки — пружини, які розгойдує прискорення голови (дихання, крок, розворот, зміна пози), плюс ледь помітний подих шуму; хвіст іде за тілом з інерцією, а кінчик хвоста сидячого чи сплячого кота час від часу смикається. Вуса колишуться, кліпання випадкове (2.2–6.5 с, іноді подвійне), сидячи кіт часом зиркає вбік.
   **День і ніч** — від теми: ніч = будь-яка тема, крім Daylight (`isNightTheme()`). Уночі `.buddy[data-night]` вмикає лампочки постійно, з м'яким неоновим ореолом (`box-shadow`). Удень лампочки темні — режим енергозбереження — і рушій блимає ними у **випадкові** моменти (WAAPI на `opacity`). Перемикач `#dayNightBtn` зберігає тему одразу, як селект теми; ніч повертає ту темну тему, що була до дня (`dayNightTarget()` пам'ятає її в `localStorage`).
   **Мурчання** — Web Audio, синтезоване один раз (`synthPurr`): ~12 м'яких поштовхів за секунду, гучніше на видиху, тихіше на вдиху, три трохи різні вдихи в зацикленому буфері. Темп задає `PURR_SLOWDOWN` (2 = удвічі повільніше за справжнього кота: 25 поштовхів за секунду користувачу здалися зашвидкими) — він розтягує і звук, і тремтіння тіла та антенок, і гудіння кнопки, але не тон. Груди кота рухаються **в такт звуку** (`purr.sample()`), тіло дрібно вібрує, антенки дзижчать. Мурчання — **не налаштування**: живе лише на цій сторінці, вимикається разом із котом і затихає, поки сторінка прихована. Увімкнути — кнопкою `#purrBtn` або клацнувши по самому котику (не по порожньому кадру: перевіряється маска пікселів пози). У компактній панелі клік по коту **не** розгортає панель — `.buddy` у списку винятків обробника кліку.
   **`hidden` на `#studyBuddy` належить рушію.** Сторінки колись ставили його щотіка; тепер це зламало б анімацію: зникнення — «пух» з іскрами, потім доріжка згортається, і лише тоді `hidden`; поява — доріжка розгортається, кіт вистрибує з іскрами. `#buddyToggleBtn` зберігає `studyBuddyEnabled` одразу, без кнопки «Зберегти»; той самий чекбокс лишається у формі налаштувань. Повноекранна сторінка за `:has(#studyBuddy:not([hidden]))` резервує смугу під кота й зменшує циферблат; її картка задач уперше стає **під** рядом кнопок кута, а не на них.
   **CSS кота живе в `buddy.js`** (`BUDDY_CSS`), а не в `sidepanel.css`: на сайтах кіт стоїть у shadow root віджета, куди жодна таблиця стилів сторінки не дістає. `create()` вставляє його на самий **початок** кореня, у який потрапив кіт (`<head>` або shadow root), тож правила сторінки — розміри, відступи, позиції — йдуть пізніше й перемагають. У `sidepanel.css` лишились тільки розміри доріжки в панелі та док.
   **Вимір — на наступному кадрі, не в колбеці `ResizeObserver`.** `measure()` пише `--px`, а від `--px` залежить висота доріжки, за якою цей самий спостерігач і стежить: зміна розміру всередині його власного колбека — це «ResizeObserver loop completed with undelivered notifications» у помилках розширення (було при переході панелі в компактний вигляд). Тому колбек лише ставить `measure()` у `requestAnimationFrame`, а `measure()` нічого не пише, якщо масштаб не змінився.
   **`.buddy` мусить мати `overflow-x: clip`.** `.buddy-walker` їде вздовж доріжки, і його бокс давав сторінці горизонтальний скрол — панель роз'їжджалась. Саме `clip`, а не `hidden`: `hidden` разом із `visible` по другій осі перетворив би обидві на `auto`, а вгору мусять вільно стирчати антенки й «z».
   `prefers-reduced-motion`: кіт не ходить і стоїть посередині, пружин і дихання немає, пози змінюються без анімації, м'ячик лежить нерухомо; кліпання й денні спалахи лампочок лишаються.
   **Перевіряти в прихованій вкладці** (як панель браузера в інструментах) незручно: там немає ні кадрів анімації, ні `ResizeObserver`, ні подій WAAPI. Для цього `buddy.step(ms)` проганяє рушій вручну, на тому самому годиннику, що й справжній цикл. Усі кадри разом — `tools/buddy-sprite/index.html`.
9. **Приватність — публічна обіцянка** (README, PRIVACY.md, лістинг): жодних зовнішніх запитів, жодного читання контенту сторінок. Не додавати fetch/аналітику/CDN.

## Реліз

Bump версії у **`manifest.json` + бейдж у `README.md` + запис у `CHANGELOG.md`** (SemVer). Перед публікацією в стор: зробити реальні скриншоти в `docs/screenshots/` (список у тамтешньому README) і замінити плейсхолдер URL приватності `https://github.com/<user>/<repo>/...` у `STORE-LISTING.md`.

В стор-архів не класти `tools/` (аркуш кадрів котика) і файли застосунку — `index.html`, `ambient.html`, `sw.js`, `manifest.webmanifest`, `app/`. Розширенню вони не потрібні; сплутати `manifest.webmanifest` з `manifest.json` рецензент не сплутає, але зайва вага й зайві питання ні до чого.

Застосунок віддається як статика з кореня репозиторію (наприклад GitHub Pages). Після правки будь-чого з `PRECACHE` у `sw.js` **підняти `CACHE`** — інакше вже встановлені копії лишаться на старих файлах.
